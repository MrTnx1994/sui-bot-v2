# sui-bot v2 — نسخه توسعه‌پذیر

نسخه جدید پروژه `sui-bot` (ربات مدیریت تلگرامی پنل S-UI).

## وضعیت
- **سورس اصلی (v1):** `/opt/sui-bot/` — سرویس فعال روی سرور، دست‌نخورده
- **نسخه جدید (v2):** `/root/sui-bot-v2/` — اینجا، برای توسعه

## ساختار
```
src/sui_bot/          ← سورس کامل (همان v1)
  bot.py              ← ربات اصلی (292KB — قلب پروژه)
  cli.py              ← رابط خط فرمان
  backup.py           ← بکاپ استریم با محدودیت حجم
  backup_bundle.py    ← بسته بکاپ با چک‌سام
  config.py           ← پیکربندی از env
  web_panel.py        ← پنل وب
  reporting.py        ← گزارش‌دهی
  sui_metadata.py     ← متادیتای پنل S-UI
  security.py         ← امنیت/نرخ درخواست
  localization.py     ← ترجمه‌ها
  navigation.py       ← ناوبری ربات
deploy/               ← systemd + web-panel
scripts/install.sh    ← نصب
.env.example          ← نمونه تنظیمات
```

## تنظیمات واقعی (در سرور، نه در v2)
- `/etc/sui-bot/sui-bot.env` — توکن‌ها و آدرس‌ها
- سرویس: `sui-bot.service` (systemd, کاربر sui-bot)
- داده: `/var/lib/sui-bot/`

## نحوه توسعه v2
1. تغییرات را در `src/sui_bot/` اعمال کن
2. تست با: `cd /root/sui-bot-v2 && .venv/bin/python -m sui_bot --help` (بعد از ساخت venv)
3. برای راه‌اندازی روی سرور: سرویس اصلی را نگه دار، نسخه تست را با venv جدا اجرا کن
4. بعد از اطمینان، می‌توان سرویس را به v2 سوییچ کرد

## به‌روزرسانی‌های فاز ۱ (قابل‌مشاهده‌سازی)
هدف: هیچ اکشنی بی‌خروجی نمی‌ماند — هر خطا دلیل واقعی خودش را در تلگرام نشان می‌دهد.

- **دلیل خطا حفظ می‌شود:** `APIClient` آخرین دلیل شکست هر endpoint را نگه می‌دارد و پیام‌های
  «Server Unresponsive» حالا علت واقعی (مثلاً `HTTP 502` یا پیام پنل) را نشان می‌دهند.
- **`sui_payload`:** پذیرش `obj` به شکل لیست (logs/changes/keypairs/users) علاوه بر دیکشنری.
- **`/diag` (فقط ادمین):** همه‌ی endpointهای GET پنل را زنده probe می‌کند و جدول سبز/قرمز با
  زمان پاسخ و پیام خطای پنل می‌دهد؛ دکمه «Re-run» هم دارد.
- **NetworkError:** دیگر بی‌صدا نیست؛ کاربر پیام «connection hiccup — try again» می‌گیرد.
- **رفع باگ NameError:** دکمه تسویه نماینده (`res_settle_request`) به هندلر واقعی وصل نبود.
