# SUI Bot — v3: درگاه زرین‌پال + کد تخفیف + اکانت تست + کیف پول

این فایل فقط **تغییرات v3** روی نسخهٔ قبلی را توضیح می‌دهد. بقیهٔ مستندات در `README.md` و `README.fa.md` است.

## قابلیت‌های جدید

### 🌐 پرداخت آنلاین (زرین‌پال)
- در فلوی فروشگاه، بعد از انتخاب اسم، صفحهٔ **انتخاب روش پرداخت** می‌آید:
  کارت‌به‌کارت / آنلاین (زرین‌پال) / کیف پول.
- تأیید پرداخت به دو روش:
  1. **خودکار** — سرور callback (`/pay/callback`) بعد از برگشت کاربر از درگاه، تراکنش را verify و کانفیگ را خودکار می‌سازد.
  2. **دستی** — دکمهٔ «✅ پرداخت کردم» داخل ربات (وقتی `ZARINPAL_CALLBACK_BASE` خالی باشد، تنها روش همین است).
- ضدتکرار: هر تراکنش فقط یک‌بار paid می‌شود (`mark_paid` idempotent) و verify دوباره (code=101) هم امن است.

### 🎟 کد تخفیف
- ادمین: `/discounts` → ساخت کد (کد، درصد، سقف استفاده، روز اعتبار) + فعال/غیرفعال + حذف.
- کاربر: در صفحهٔ روش پرداخت دکمهٔ «اعمال کد تخفیف» → مبلغ سفارش همان لحظه کم می‌شود.
- هر کد یک‌بار برای هر کاربر؛ تخفیف هرگز مبلغ را زیر ۱۰۰۰ تومان نمی‌برد.
- مصرف کد فقط بعد از پرداخت قطعی ثبت می‌شود (هر سه مسیر).

### 🎁 اکانت تست رایگان
- ۵۰۰ مگابایت / ۱ روز — فقط یک‌بار برای هر کاربر تلگرام.
- منوی اصلی → «🎁 اکانت تست رایگان» یا دستور `/trial`.
- ساخت خودکار کلاینت در پنل (اسم `t` + هگز رندوم، گروه `trial`).
- `TRIAL_INBOUND_ID` = 0 → روی همهٔ اینباندهای فروشگاه؛ عدد داده شود → فقط آن اینباند.

### 💼 کیف پول داخلی
- همان استور نمایندگی (`resellers.json`) — موجودی مشترک با سود زیرمجموعه.
- منوی اصلی → «💼 کیف پول» یا `/wallet` → موجودی + شارژ آنلاین.
- پرداخت سفارش از کیف پول: کسر آنی؛ اگر ساخت کانفیگ شکست بخورد، **مبلغ خودکار برمی‌گردد**.
- شارژ آنلاین: مبلغ بفرست (حداقل `ZARINPAL_MIN_TOMAN`) → درگاه → شارژ خودکار.

## متغیرهای محیطی جدید

```env
# زرین‌پال — خالی = درگاه غیرفعال (فقط کارت‌به‌کارت)
ZARINPAL_MERCHANT_ID=
ZARINPAL_SANDBOX=false          # true فقط برای تست
ZARINPAL_MIN_TOMAN=50000        # حداقل شارژ کیف پول (تومان)
ZARINPAL_CALLBACK_BASE=         # مثل https://pay.example.com — خالی = تأیید با دکمهٔ ربات
ZARINPAL_CALLBACK_BIND=127.0.0.1
ZARINPAL_CALLBACK_PORT=8098

# اکانت تست رایگان
TRIAL_ENABLED=true
TRIAL_INBOUND_ID=0              # 0 = همهٔ اینباندهای فروشگاه
```

## راه‌اندازی callback زرین‌پال (اختیاری ولی توصیه‌شده)

سرور روی `127.0.0.1:8098` بالا می‌آید؛ پشت nginx مثلاً:

```nginx
server {
    server_name pay.example.com;
    location /pay/ {
        proxy_pass http://127.0.0.1:8098;
        proxy_set_header Host $host;
    }
}
```

سپس `ZARINPAL_CALLBACK_BASE=https://pay.example.com` و ری‌استارت ربات.
در پنل زرین‌پال نیازی به تنظیم callback جداگانه نیست — authority خودش لینک را می‌سازد.

## فایل‌های دادهٔ جدید

| فایل | محتوا |
|---|---|
| `payments.json` | تراکنش‌های آنلاین (خرید + شارژ کیف پول) |
| `discounts.json` | کدهای تخفیف + مصرف هر کاربر |
| `trial_users.json` | کاربرانی که تست رایگان گرفته‌اند |

همه کنار `shop_orders.json` در `STORE_DATA_DIR` (یا `DATA_DIR`).

## دستورات جدید

| دستور | مخاطب | کار |
|---|---|---|
| `/trial` | کاربر | اکانت تست رایگان |
| `/wallet` | کاربر | موجودی + شارژ |
| `/discounts` | ادمین | مدیریت کدهای تخفیف |

## نکتهٔ امنیتی

- مرچنت‌کد فقط در env — هرگز در کد/لاگ نوشته نمی‌شود.
- دکمه‌های تأیید/بررسی فقط برای صاحب تراکنش (یا ادمین) کار می‌کنند.
- سرور callback فقط status=OK را verify می‌کند و تراکنش pending را می‌پذیرد (ضد replay).
